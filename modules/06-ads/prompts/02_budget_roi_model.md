# PART A · 盈亏线

```bash
python3 scripts/ad_metrics.py calc --market us --price 39.99 --product-cost 12 \
    --referral-pct 6 --payment-pct 2 --return-pct 2
```

输出：广告前贡献 / 盈亏线 ROAS / 盈亏线 ACoS。

**必须展示代入过程**，让使用者能复核：

```
广告前贡献 = 39.99 − 12 − 4 − 39.99×(6%+2%+2%) = 20.00
盈亏线 ROAS = 39.99 ÷ 20.00 = 2.00
```

## ROAS 敏感性表（必出）

| ROAS | 广告费/单 | 剩余毛利/单 | 判定 |
|---|---|---|---|
| 1.5 | | 负数 | ❌ 亏 |
| 2.0（盈亏线） | | ~0 | ⚠️ 平衡 |
| 3.0 | | | ✅ |
| 5.0 | | | ✅ |

## 差距过大时的路径

| 路径 | 做法 | 代价 |
|---|---|---|
| 提价 | 重算目标价，把广告成本预留进售价 | 影响转化 |
| 只做冷启动 | 广告跑出自然流量后降预算 | 起量慢 |
| 换成本 | 换供应商/物流 | 周期长 |
| 提客单 | 高配 SKU / Bundle | 需要产品支持 |
| 放弃 | 利润结构不成立 | 沉没 |

# PART B · 预算模型

**最大预算取决于市场容量**，不是越高越好：容量小的时候加预算只提高花费，不带来订单。

**目标 ROAS 不要一开始就设到盈亏线附近** —— 越接近盈亏线越难跑出去，样本越少，越判不准。
先跑出样本，再逐步收紧。

## 分阶段（每 7 天一段）

| 阶段 | 目标 | 通过条件 | 未通过 |
|---|---|---|---|
| 第 1 周 | 跑出样本 | 曝光/点击/订单达最小量 | 检查预算与定向是否太窄 |
| 第 2 周 | 判定漏斗 | 各环回到阈值 | 回 01_funnel_diagnosis |
| 第 3 周 | 收敛 ROAS | ROAS ≥ 盈亏线 | 砍长期不达标的组 |
| 第 4 周 | 放量 | 保持 ROAS 同时加预算 | 每次 +20~30%，观察 3 天 |

**每阶段只推进一项**：样本与效率是冲突目标。

# PART C · 预算节律

TikTok 支持分时段设置。暂停投放对账户权重的影响，以你实际观察到的为准，不要凭传闻操作。
建议：把预算集中到你的转化高峰时段，其余时段压到最低可跑量。

**时区换算必须自己确认**（卖家所在地 vs 市场时区），不要凭印象。
